

Личный планировщик: неделя строится вокруг одной темы и 3 целей. Expo (React Native + TypeScript) + Supabase.

Статус: **Этап 4** — шесть разделов: «Неделя», «Сегодня», «Входящие», «Расписание»,
«Обзор», «Календарь». Постоянные блоки расписания и разовые блоки дня, задачи с
привязкой к целям, напоминания, свободное время внутри настраиваемых границ дня,
календарь на год с отметками важных дней и заметки по спискам.

## Запуск

### 1. Supabase

1. Создайте проект на [supabase.com](https://supabase.com) (если ещё не создан).
2. В SQL Editor выполните миграции из [`supabase/migrations/`](./supabase/migrations) по порядку:
   `0001_init.sql` — 5 таблиц (`weeks`, `goals`, `tasks`, `schedule_blocks`, `notes`) с ограничениями и RLS;
   `0002_events.sql` — разовые блоки дня (`events`); `0003_user_settings.sql` — границы дня (`user_settings`);
   `0004_block_period.sql` — срок действия пары (`starts_on`/`ends_on`);
   `0005_day_marks.sql` — отметки важных дней (`day_marks`); `0006_note_lists.sql` — списки заметок.
3. В Authentication → Providers включите **Email** и выключите **Confirm email**: вход идёт по email + паролю, писем приложение не шлёт. Подтверждение адреса здесь только мешает — встроенная почта Supabase отправляет письма лишь участникам проекта, остальные не смогли бы войти.
4. Скопируйте Project URL и `anon` key: Project Settings → API.

### 2. Переменные окружения

```bash
cp .env.example .env
```

Впишите в `.env`:

```
EXPO_PUBLIC_SUPABASE_URL=https://xxxxxxxxxxxx.supabase.co
EXPO_PUBLIC_SUPABASE_ANON_KEY=ваш-anon-key
```

`.env` в `.gitignore`, в репозиторий не попадёт.

### 3. Зависимости и запуск

```bash
npm install
npx expo start
```

Дальше в терминале Expo:

- `w` — открыть веб-версию в браузере
- отсканировать QR в приложении **Expo Go** — запуск на телефоне (Android/iOS)
- `a` / `i` — Android/iOS эмулятор, если настроен локально

### 4. Вход

На экране входа — email и пароль. Нет аккаунта → вкладка «Регистрация»: аккаунт создаётся сразу,
без письма с подтверждением (при условии, что в Supabase выключен **Confirm email**). Сессия
сохраняется (AsyncStorage на телефоне, localStorage в браузере), выход — кнопка «Выйти» в шапке
любого раздела.

#### Вход через Google

Кнопка «Войти через Google» на экране входа есть всегда. Пока провайдер не настроен,
она честно пишет, что он выключен. Настройка разовая, в двух местах.

**1. Google Cloud Console** → [APIs & Services → Credentials](https://console.cloud.google.com/apis/credentials)

1. Create credentials → OAuth client ID → тип **Web application**.
2. **Authorized JavaScript origins** — откуда открывается приложение:
   `http://localhost:8081` для локальной разработки и адрес деплоя
   `https://<ваш-сайт>.onrender.com`.
3. **Authorized redirect URIs** — сюда Google возвращает пользователя. Это адрес
   **Supabase**, а не вашего сайта:
   - локально: `http://127.0.0.1:54321/auth/v1/callback`
   - облако: `https://<project-ref>.supabase.co/auth/v1/callback`
4. Скопируйте **Client ID** и **Client secret**.

**2а. Локальный Supabase**

Положите ключи в корневой `.env` (его читает Supabase CLI, в бандл приложения они
не попадают — префикса `EXPO_PUBLIC_` у них нет):

```
SUPABASE_AUTH_EXTERNAL_GOOGLE_CLIENT_ID=...
SUPABASE_AUTH_EXTERNAL_GOOGLE_SECRET=...
```

В [`supabase/config.toml`](./supabase/config.toml) в секции `[auth.external.google]`
поставьте `enabled = true` и перезапустите базу — конфиг читается только при старте:

```bash
npx supabase stop && npx supabase start
```

**2б. Облачный Supabase**

- Authentication → Providers → **Google**: включить, вставить Client ID и Client Secret.
- Authentication → URL Configuration: **Site URL** — адрес деплоя, в **Redirect URLs**
  добавить `https://<ваш-сайт>.onrender.com/**`. Без этого Supabase вернёт
  пользователя не туда, и вход молча не сработает.

**Как это устроено.** Везде один и тот же flow — PKCE (`flowType: "pkce"` в
[`lib/supabase.ts`](./lib/supabase.ts)): Google возвращает одноразовый код, который
[`lib/auth/google.ts`](./lib/auth/google.ts) меняет на сессию через
`exchangeCodeForSession`.

- В браузере страница уходит на Google и возвращается на `/login?code=...`. Код
  разбирает `completeGoogleRedirect` при загрузке экрана входа, после чего чистит
  адресную строку. Встроенный в supabase-js `detectSessionInUrl` специально
  выключен: он делает то же самое, но про неудачный обмен молчит — человек видел бы
  пустую форму входа и `?code=` в адресе, без единого слова о причине.
- На телефоне окно Google открывает `expo-web-browser`, возврат идёт по схеме
  `notebook://auth-callback`, и обмен происходит сразу после закрытия окна.

Перед тем как увести на Google, приложение тихо дёргает ссылку `/authorize` у
Supabase. Рабочая настройка отвечает редиректом, сломанная — понятным JSON, который
и превращается в сообщение на экране входа. Без этой проверки человек вместо ошибки
увидел бы голый английский JSON на чужой странице.

**На телефоне нужен development build.** В Expo Go схема приложения чужая
(`exp://...`), и Expo прямо предупреждает, что OAuth там проверять не стоит. Соберите
свой клиент: `npx expo run:android` / `npx expo run:ios` либо
`eas build --profile development`.

#### Почему не код из письма

Вход по 6-значному коду (`signInWithOtp`) убран, потому что письмо почти никогда не доходит:

- локальный Supabase **не отправляет письма наружу** — всё оседает во встроенном почтовике
  Inbucket на <http://127.0.0.1:54324>;
- облачный Supabase на встроенной почте шлёт письма **только участникам проекта** и с жёстким
  лимитом в несколько штук в час.

Чтобы вернуть вход по коду, нужен свой SMTP (Resend, Brevo, SendGrid) в
Project Settings → Authentication → SMTP Settings — после этого письма пойдут на любые адреса.

#### Пропустить вход на время разработки

Если вводить пароль на каждый перезапуск неудобно, можно временно отключить экран входа:
в `.env` добавьте `EXPO_PUBLIC_DEV_SKIP_LOGIN=true`.

Приложение само войдёт под фиксированным dev-аккаунтом `dev@notebook.local` (его создаёт
[`supabase/seed.sql`](./supabase/seed.sql)) и сразу откроет «Неделю», минуя экран логина.
Аккаунт настоящий, так что `auth.uid()` и RLS работают как обычно, а данные видны одинаково
в любом браузере и вкладке. Чтобы вернуть обычный вход — уберите переменную или поставьте `false`.

**На публичный деплой эту переменную класть нельзя**: она пускает в приложение кого угодно.

## Деплой веб-версии на Render

Настройка лежит в [`render.yaml`](./render.yaml) — Render читает его сам
(Blueprint), руками в панели ничего собирать не надо. Сборка: `npm ci &&
npx expo export -p web`, результат — статика в `dist/`.

`web.output = "static"` означает, что каждый экран собирается в свой файл
(`dist/week.html`, `dist/login.html` и т.д.). Запрос приходит на `/week`, такого
файла нет — поэтому в `render.yaml` для каждого роута прописан rewrite, а в конце
общий фолбэк на `/index.html`. **Добавили новый экран в `app/` — добавьте и rewrite**,
иначе прямая ссылка на него вернёт главную.

Переменные окружения задаются в панели Render (в `render.yaml` они помечены
`sync: false`, значений в репозитории нет):

| Переменная | Значение |
| --- | --- |
| `EXPO_PUBLIC_SUPABASE_URL` | адрес облачного проекта Supabase |
| `EXPO_PUBLIC_SUPABASE_ANON_KEY` | `anon`-ключ оттуда же |

Всё, что начинается с `EXPO_PUBLIC_`, попадает прямо в бандл и видно любому
посетителю. `anon`-ключ такой по задумке — доступ режет RLS. А вот
`EXPO_PUBLIC_DEV_SKIP_LOGIN` на Render класть нельзя — пускает в приложение
кого угодно. Ключ OpenAI в бандл не попадает вообще — см. «Ключ OpenAI» ниже.

После того как сайт поднялся, в облачном Supabase нужно разрешить ему вход
(Authentication → URL Configuration): **Site URL** — адрес сайта, в **Redirect URLs** —
`https://<ваш-сайт>.onrender.com/**`. Для входа через Google тот же адрес идёт в
**Authorized JavaScript origins** в Google Cloud Console. Без этого вход возвращает
не туда.

Проверить сборку локально, не дожидаясь Render:

```bash
npx expo export -p web   # собрать в dist/
npx expo serve           # раздать dist/ так же, как это сделает Render
```

## Структура

```
app/              экраны (Expo Router)
  _layout.tsx     провайдеры, корневой Stack
  index.tsx       редирект: сессия есть → /week, нет → /login
  login.tsx       вход и регистрация по email + паролю, кнопка Google
  (app)/          защищённая группа — 5 разделов
    _layout.tsx   проверка сессии + AppShell (нижние вкладки / боковое меню)
    week.tsx, today.tsx, inbox.tsx, schedule.tsx, review.tsx, calendar.tsx
components/       AppShell (адаптивная навигация), карточка дня, формы блока, задачи и
                  заметки, цели недели, границы дня, месяц и год календаря, панель дня
lib/
  supabase.ts     клиент Supabase
  api.ts          вся работа с БД — CRUD по таблицам
  blocks.ts       блоки дня, свободные окна внутри границ дня
  noteLists.ts    пять списков заметок
  useDayWindow.ts границы дня из user_settings (с запасными значениями)
  queryKeys.ts    ключи react-query
  types.ts        типы, соответствующие схеме БД
  date.ts         дата/неделя в часовом поясе Asia/Almaty
  theme.ts        цвета офисного стиля
  store/auth.ts   zustand-стор сессии
supabase/migrations/        схема БД + RLS, события, настройки
```

Навигация: на телефоне (ширина < 768px) — нижние вкладки, от 768px — боковое меню.

Границы дня (по умолчанию 08:00–22:00) задаются на экране «Расписание» — внутри них
«Неделя», «Сегодня» и «Обзор» считают свободное время.

У пары расписания есть необязательный срок действия («Пара идёт с … по …»). Курс
закончился — впишите последнюю дату, и со следующего дня пара перестаёт попадать в
«Неделю», «Сегодня» и «Обзор», а её время считается свободным. На «Расписании» такая
пара остаётся видимой, блёклой и с пометкой «завершена», так что срок можно изменить
или снять.

## Календарь

Отдельный раздел после «Обзора». Наверху — полоса «365 дней»: квадрат на каждый день
года, прожитые дни заполнены, насыщенность — по числу сделанных задач, важные дни
обведены, сегодня выделен; рядом счётчик «День N из 365». Ниже — все 12 месяцев; под
числом видно, что в этом дне: цветные точки — важное, серая или зелёная — задачи,
синяя — напоминание. Клик по любому дню (в месяце или в полосе года) открывает панель
дня: отметить важное, добавить задачу, поставить время и напоминание.

### Напоминания

Время напоминания хранится в `tasks.remind_at`, а в назначенный момент приходит
системное уведомление (`expo-notifications`, локальные уведомления).

Как это устроено: источник правды — база. Хук `lib/useReminderSync.ts` следит за
списком незакрытых задач с напоминанием в будущем и при каждом его изменении
переназначает расписание уведомлений целиком (`lib/notifications.ts`): снимает
старые и ставит заново. Так телефон не расходится с базой, если задачу поправили с
другого устройства. Разрешение на уведомления спрашивается не на старте, а когда
появляется первое напоминание.

Где работает: на телефоне (в Expo Go локальные уведомления приходят; для своей иконки
и цвета нужен dev build — `npx expo run:android` или `eas build --profile development`).
**В браузере уведомлений нет** — там напоминание только сохраняется, и форма об этом
честно пишет.

## Заметки

«Входящие» — доска из колонок в духе Google Tasks: «Задачи» (задачи без даты) и пять
списков заметок — **Фокус**, **Идеи**, **Учёба**, **Личные**, **Архив**. Колонки стоят
рядом и листаются вбок; на узком экране колонка занимает ширину экрана.

Колонка у всех одна и та же (`components/BoardColumn.tsx`), поэтому задачи и заметки
выглядят и ведут себя одинаково: строка «+ Добавить…» сверху, кружок слева закрывает
запись, «×» справа удаляет, нажатие на текст открывает форму. Закрытые записи уезжают
в свёрнутый блок «N выполнено»; когда в колонке не осталось открытых — «Всё закрыто».

В форме заметки — текст, цвет из общей палитры (цветная полоса слева в строке) и выбор
списка: так заметка переносится, в том числе в архив.

## Темы

Три темы: **Светлая**, **Тёмная** и **Тёплая** (кремовая, без чистого белого — меньше
устают глаза вечером). Переключатель — одна кнопка вверху бокового меню, под названием
приложения (на телефоне — над нижними вкладками): показывает текущую тему, нажатие
даёт следующую по кругу. Три отдельные кнопки внизу меню переносились на две строки и
терялись, поэтому их заменила одна. Выбор сохраняется между запусками (AsyncStorage).

Палитра живёт в `lib/theme.ts`: тип `Palette`, три набора цветов и zustand-стор.
Компоненты берут цвета хуком `useColors()` и строят стили от него
(`const styles = useMemo(() => createStyles(colors), [colors])`), поэтому тема
меняется на лету, без перезапуска. Цвета блоков и целей (`BLOCK_COLORS`,
`GOAL_COLORS`) от темы не зависят — они опознавательные.

## Финансы

Раздел «Финансы»: за выбранный месяц — сколько пришло, сколько ушло, остаток;
разбивка трат по категориям с долями; список операций; ручное добавление.
Операции лежат в `transactions` (сумма всегда положительная, знак — в `direction`).

**Разбор выписки.** Кнопка «Выбрать PDF» отправляет файл целиком в OpenAI
(Responses API, `input_file`), модель возвращает JSON: операции с категориями,
короткий вывод и общие соображения. Найденное показывается списком и попадает в
базу только после кнопки «Сохранить операции» — сверяйте суммы, модель ошибается.

**Чат** — отдельный раздел меню под «Финансами». Это полноэкранный разговор:
подсказки для начала, пузыри вопросов и ответов, поле ввода внизу, «Очистить».
Вопрос уходит вместе со сводкой за текущий месяц (пришло, ушло, категории),
поэтому ответы про ваши траты, а не вообще. Переписка не сохраняется — живёт до
перезагрузки.

Ответы ИИ — общие соображения, а не индивидуальная инвестиционная рекомендация;
это написано и в интерфейсе.

### Ключ OpenAI

Запрос к OpenAI идёт не из приложения напрямую, а через Supabase Edge Function
[`openai-proxy`](./supabase/functions/openai-proxy/index.ts) — ключ хранится
только на сервере (секрет, не переменная `EXPO_PUBLIC_*`) и в бандл не попадает.
Вызвать функцию может только залогиненный пользователь приложения: Supabase
проверяет JWT ещё на шлюзе, раньше кода функции.

```
OPENAI_API_KEY=sk-...
EXPO_PUBLIC_OPENAI_MODEL=gpt-4o-mini
```

`OPENAI_API_KEY` — без префикса `EXPO_PUBLIC_`. Локально кладётся в корневой
`.env`, его подхватывает `supabase/config.toml` (`[edge_runtime.secrets]`) при
`supabase start`. `EXPO_PUBLIC_OPENAI_MODEL` не секрет (просто название модели),
его видно всем, и это нормально.

На облачном Supabase секрет задаётся отдельно и на Render вообще не нужен:

```bash
npx supabase secrets set OPENAI_API_KEY=sk-... --project-ref <project-ref>
npx supabase functions deploy openai-proxy --project-ref <project-ref>
```

Повторять `functions deploy` нужно после любого изменения кода функции.
