

Личный планировщик: неделя строится вокруг одной темы и 3 целей. Expo (React Native + TypeScript) + Supabase.

Статус: **Этап 4** — шесть разделов: «Неделя», «Сегодня», «Входящие», «Расписание»,
«Обзор», «Календарь». Постоянные блоки расписания и разовые блоки дня, задачи с
привязкой к целям, напоминания, свободное время внутри настраиваемых границ дня,
календарь на год с отметками важных дней и заметки по спискам.

## Запуск

### 1. Supabase

1. Создайте проект на [supabase.com](https://supabase.com) (если ещё не создан).
2. В SQL Editor выполните миграции из [`supabase/migrations/`](./supabase/migrations) по порядку:
   `0001_init.sql` — 5 таблиц (`weeks`, `goals`, `tasks`, `schedule_blocks`, `notes`) с ограничениями и RLS;
   `0002_events.sql` — разовые блоки дня (`events`); `0003_user_settings.sql` — границы дня (`user_settings`);
   `0004_block_period.sql` — срок действия пары (`starts_on`/`ends_on`);
   `0005_day_marks.sql` — отметки важных дней (`day_marks`); `0006_note_lists.sql` — списки заметок.
3. В Authentication → Providers включите **Email** (OTP-код на почту, без пароля). Если нужно сразу входить без подтверждения домена — можно оставить настройки по умолчанию.
4. Скопируйте Project URL и `anon` key: Project Settings → API.

### 2. Переменные окружения

```bash
cp .env.example .env
```

Впишите в `.env`:

```
EXPO_PUBLIC_SUPABASE_URL=https://xxxxxxxxxxxx.supabase.co
EXPO_PUBLIC_SUPABASE_ANON_KEY=ваш-anon-key
```

`.env` в `.gitignore`, в репозиторий не попадёт.

### 3. Зависимости и запуск

```bash
npm install
npx expo start
```

Дальше в терминале Expo:

- `w` — открыть веб-версию в браузере
- отсканировать QR в приложении **Expo Go** — запуск на телефоне (Android/iOS)
- `a` / `i` — Android/iOS эмулятор, если настроен локально

### 4. Вход

На экране входа введите email → придёт 6-значный код на почту → введите код. Сессия сохраняется (AsyncStorage на телефоне, localStorage в браузере).

#### Пропустить вход на время разработки

Если на каждый перезапуск вводить код из письма неудобно, можно временно отключить экран входа:

1. В Supabase: Authentication → Settings → включите **Allow anonymous sign-ins**.
2. В `.env` добавьте `EXPO_PUBLIC_DEV_SKIP_LOGIN=true`.

Приложение само создаст анонимную Supabase-сессию (настоящий `auth.uid()`, RLS работает как обычно) и сразу откроет «Неделю», минуя экран логина. Чтобы вернуть обычный вход — уберите переменную или поставьте `false`.

## Структура

```
app/              экраны (Expo Router)
  _layout.tsx     провайдеры, корневой Stack
  index.tsx       редирект: сессия есть → /week, нет → /login
  login.tsx       вход по email (OTP-код)
  (app)/          защищённая группа — 5 разделов
    _layout.tsx   проверка сессии + AppShell (нижние вкладки / боковое меню)
    week.tsx, today.tsx, inbox.tsx, schedule.tsx, review.tsx, calendar.tsx
components/       AppShell (адаптивная навигация), карточка дня, формы блока, задачи и
                  заметки, цели недели, границы дня, месяц и год календаря, панель дня
lib/
  supabase.ts     клиент Supabase
  api.ts          вся работа с БД — CRUD по таблицам
  blocks.ts       блоки дня, свободные окна внутри границ дня
  noteLists.ts    пять списков заметок
  useDayWindow.ts границы дня из user_settings (с запасными значениями)
  queryKeys.ts    ключи react-query
  types.ts        типы, соответствующие схеме БД
  date.ts         дата/неделя в часовом поясе Asia/Almaty
  theme.ts        цвета офисного стиля
  store/auth.ts   zustand-стор сессии
supabase/migrations/        схема БД + RLS, события, настройки
```

Навигация: на телефоне (ширина < 768px) — нижние вкладки, от 768px — боковое меню.

Границы дня (по умолчанию 08:00–22:00) задаются на экране «Расписание» — внутри них
«Неделя», «Сегодня» и «Обзор» считают свободное время.

У пары расписания есть необязательный срок действия («Пара идёт с … по …»). Курс
закончился — впишите последнюю дату, и со следующего дня пара перестаёт попадать в
«Неделю», «Сегодня» и «Обзор», а её время считается свободным. На «Расписании» такая
пара остаётся видимой, блёклой и с пометкой «завершена», так что срок можно изменить
или снять.

## Календарь

Отдельный раздел после «Обзора». Наверху — полоса «365 дней»: квадрат на каждый день
года, прожитые дни заполнены, насыщенность — по числу сделанных задач, важные дни
обведены, сегодня выделен; рядом счётчик «День N из 365». Ниже — все 12 месяцев; под
числом видно, что в этом дне: цветные точки — важное, серая или зелёная — задачи,
синяя — напоминание. Клик по любому дню (в месяце или в полосе года) открывает панель
дня: отметить важное, добавить задачу, поставить время и напоминание.

### Напоминания

Время напоминания хранится в `tasks.remind_at`, а в назначенный момент приходит
системное уведомление (`expo-notifications`, локальные уведомления).

Как это устроено: источник правды — база. Хук `lib/useReminderSync.ts` следит за
списком незакрытых задач с напоминанием в будущем и при каждом его изменении
переназначает расписание уведомлений целиком (`lib/notifications.ts`): снимает
старые и ставит заново. Так телефон не расходится с базой, если задачу поправили с
другого устройства. Разрешение на уведомления спрашивается не на старте, а когда
появляется первое напоминание.

Где работает: на телефоне (в Expo Go локальные уведомления приходят; для своей иконки
и цвета нужен dev build — `npx expo run:android` или `eas build --profile development`).
**В браузере уведомлений нет** — там напоминание только сохраняется, и форма об этом
честно пишет.

## Заметки

«Входящие» — доска из колонок в духе Google Tasks: «Задачи» (задачи без даты) и пять
списков заметок — **Фокус**, **Идеи**, **Учёба**, **Личные**, **Архив**. Колонки стоят
рядом и листаются вбок; на узком экране колонка занимает ширину экрана.

Колонка у всех одна и та же (`components/BoardColumn.tsx`), поэтому задачи и заметки
выглядят и ведут себя одинаково: строка «+ Добавить…» сверху, кружок слева закрывает
запись, «×» справа удаляет, нажатие на текст открывает форму. Закрытые записи уезжают
в свёрнутый блок «N выполнено»; когда в колонке не осталось открытых — «Всё закрыто».

В форме заметки — текст, цвет из общей палитры (цветная полоса слева в строке) и выбор
списка: так заметка переносится, в том числе в архив.

## Темы

Три темы: **Светлая**, **Тёмная** и **Тёплая** (кремовая, без чистого белого — меньше
устают глаза вечером). Переключатель — одна кнопка вверху бокового меню, под названием
приложения (на телефоне — над нижними вкладками): показывает текущую тему, нажатие
даёт следующую по кругу. Три отдельные кнопки внизу меню переносились на две строки и
терялись, поэтому их заменила одна. Выбор сохраняется между запусками (AsyncStorage).

Палитра живёт в `lib/theme.ts`: тип `Palette`, три набора цветов и zustand-стор.
Компоненты берут цвета хуком `useColors()` и строят стили от него
(`const styles = useMemo(() => createStyles(colors), [colors])`), поэтому тема
меняется на лету, без перезапуска. Цвета блоков и целей (`BLOCK_COLORS`,
`GOAL_COLORS`) от темы не зависят — они опознавательные.

## Финансы

Раздел «Финансы»: за выбранный месяц — сколько пришло, сколько ушло, остаток;
разбивка трат по категориям с долями; список операций; ручное добавление.
Операции лежат в `transactions` (сумма всегда положительная, знак — в `direction`).

**Разбор выписки.** Кнопка «Выбрать PDF» отправляет файл целиком в OpenAI
(Responses API, `input_file`), модель возвращает JSON: операции с категориями,
короткий вывод и общие соображения. Найденное показывается списком и попадает в
базу только после кнопки «Сохранить операции» — сверяйте суммы, модель ошибается.

**Чат** — отдельный раздел меню под «Финансами». Это полноэкранный разговор:
подсказки для начала, пузыри вопросов и ответов, поле ввода внизу, «Очистить».
Вопрос уходит вместе со сводкой за текущий месяц (пришло, ушло, категории),
поэтому ответы про ваши траты, а не вообще. Переписка не сохраняется — живёт до
перезагрузки.

Ответы ИИ — общие соображения, а не индивидуальная инвестиционная рекомендация;
это написано и в интерфейсе.

### Ключ OpenAI

```
EXPO_PUBLIC_OPENAI_API_KEY=sk-...
EXPO_PUBLIC_OPENAI_MODEL=gpt-4o-mini
```

⚠️ Любая переменная `EXPO_PUBLIC_*` попадает в бандл приложения — ключ сможет
достать каждый, у кого есть сборка. Так можно **только для локальной проверки**.
Перед тем как отдавать приложение кому-то, запрос нужно унести на сервер
(Supabase Edge Function) и ходить туда: в коде меняются только адрес и заголовок
в `lib/ai/statement.ts` и `lib/ai/chat.ts`. После проверки ключ стоит отозвать в
панели OpenAI и выпустить новый.
